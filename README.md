# Interchange Generator —— 天际线2 立交桥生成 Mod

在 Cities: Skylines II 中**整体摆放**一座立交：选三向/四向 → 选立交类型 → 设每层海拔 → 对准已有道路方向 → 一次放下。

## 产品定位

| | InterchangeBuilder（已有 mod） | 本 mod |
|---|---|---|
| 思路 | 节点连线：用不同曲线把两个节点连起来 | **整体摆放**：一个完整立交作为整体预览、旋转、放置 |
| 产出 | 单条匝道 | 整座立交（主线、被交道路、全部匝道） |
| 与路网关系 | 直接连接节点 | 方向**匹配**已有道路，臂端是否接入可选，默认不强制 |
| 高度 | 逐条调整 | **按层**设海拔，支持地上多层、地上地下混合 |

## 关键设计

### 1. 高度是「相对地面」而不是绝对值
生成层局部坐标里的 Y = **离地高度**（elevation），不是世界高度。落地层对每个控制点采样地形：
`世界 Y = 地形高度(x, z) + elevation`，同时写入 `CoursePos.m_Elevation = elevation`。
这样立交放在坡地上，各层仍保持设定的离地高度。

### 2. 层（Level）模型：基层 + 层间高差
`InterchangeParams.Levels = [{ 名称, 海拔 }, …]`。每条直行道路属于某一层；匝道连接两层，坡度由两层海拔差和匝道长度决定。

用户不直接设每层海拔，而是设**基层（下层）海拔**，其他层 = 基层 + 层间高差（`LevelPlanner`）：
- 改基层高度，整座立交一起升降，各层关系不变；
- 层间高差默认**自动**：取这两种道路之间需要的最小净空（按道路竖向范围计算，不低于实测 7.5 米），也可手动设，小于最小值时报错；
- 可选哪条道路在上层（默认被交道路在上）；
- 面板显示每层实际高度和所在分段（高架/路堤/下沉路堑/隧道）。

**后续**：自动连接（阶段 7）时，基层高度取外部道路最低连接节点的离地高度。**隧道**（任一层 ≤ −13 米）另需考虑：洞口位置、与地形的覆土深度、隧道层与地面层之间的净空规则，届时单独处理。

### 3. 汇入臂（Leg）模型
`InterchangeParams.Legs = 3 或 4 × { 角度, 道路预制体, 所在层, 引道长度 }`。模板按臂的实际角度生成几何，不再假定 90° 正交。

### 4. 高度分段与净空（游戏代码 + 游戏内实测）
普通道路 `m_ElevationLimit = 4` 米，游戏按道路**左右两侧边缘**各自测离地高度（坡地上会和设定值有出入），规则见 `NetCompositionHelpers.GetElevationFlags`：
- ≥ 8 米（2 × 4，取 8.5 留余量）→ **高架桥**（有立柱，下方可通行）
- 4 ~ 8 米 → **路堤**（实心、带挡土墙，下方**不能**通行）——游戏内实测上层 7.5 米时就是路堤，挡住下层报“物体重叠”
- −4 ~ 4 米 → 地面
- 跨越其他道路的上层必须是高架桥；自动层间高差会把上层提到至少 8.5 米。基层是隧道时，自动把上层放在地面（0 米）
- −4 ~ −13 米 → 下沉路堑；≤ −13 米（游戏代码为 −3 × 4 = −12 米，按道路边缘测高度后实测需 −13 米）或道路带 `LoweredIsTunnel` → 隧道
- **上下层净空**：游戏用两条道路的竖向范围（`NetGeometryData.m_DefaultHeightRange` / `m_ElevatedHeightRange`）做 3D 碰撞，上层的结构底不能伸进下层的净空顶。实测：**交叉跨越至少 7.5 米，上下平行重叠（双层）至少 10 米**；校验取「按预制体数据算出的值」与实测值中的较大者（`HeightRange.RequiredGap`）
- **匝道不能比主线宽**：否则分流节点无法成形，游戏报“形状无效”
- **分流段是与主线相切的曲线（外切曲线），长度由角度算出**：游戏的分流节点会延伸到两条路边缘不再重叠处（约 (主线半宽 + 匝道半宽) ÷ tan 分流角，公路规则的节点还会更长）。分流段若比节点短或是 S 形，游戏报“形状无效/重叠”（早期实测）。现在分流段从与主线相切逐渐转到分流角（只朝一个方向弯），保持主线高度，长度 = 2 × (主线半宽 + 匝道半宽 + 3 米) ÷ tan 分流角；之后的爬坡段切线连续。所有立交的匝道都与所接道路相切（菱形用外切曲线，苜蓿叶、喇叭、涡轮、堆栈等用内切曲线）。匝道坡度上限取 8% 与匝道道路自身 `m_MaxSlopeSteepness` 中较严者
- **双向主线只能在地面分出匝道**：双向道路的节点在路中心，高架/下沉/隧道中从路中心分出匝道时游戏报“形状无效”；这些情况必须用双幅（或以后的双向→双幅过渡段）
- **立柱与自动切分**（`PillarPlanner`）：上层高架的立柱出现在 ① 节点；② 游戏切分点（超过 `m_ElevatedLength` = 80 米的路段被等分）；③ 带“中部立柱”的道路在每段中部——无间距时正中一根，有间距 S 时 n = ⌊L/S − 0.5⌋ 根均布（L < 1.5S 时没有）。立柱数据从道路预制体 `SubObject`（EdgePlacement + MiddlePlacement 的 `PillarData` 对象）读出。规划跨越段时依次尝试：对称且无中部立柱 → 中部立柱落在下层双幅的分隔带里 → 向一侧加长让中部立柱越过下层道路；都不行时报错。下层道路也在交叉点两侧各加节点，使游戏切分的切点不落在交叉点
- **相交角度 45°~135°**：匝道接口离主线的垂直距离固定（RampTerminalOffset），匝道末端方向取“平行主线”和“垂直被交道路”的角平分线，和被交道路至少成 67.5°（游戏内实测：平行到达时斜交过大报“形状无效/重叠”，完全垂直又让匝道急转成 S 形）。
- **公路不允许平行叠层**（游戏本身限制，游戏内实测）
- **游戏报错与警告**：面板区分阻止放置的错误（图标优先级 Error）和不阻止的警告（Warning，如可被覆盖的物体）；错误区单独固定在设置区下方，滚动设置时也看得到
- 每种道路有允许范围 `PlaceableNetData.m_ElevationRange`；超出时要换成它的 `m_UndergroundPrefab`。落地层负责这个切换。

### 5. 方向匹配（`JunctionReader` + `JunctionMatcher`，已在游戏内验证）
- **立体交叉（虚拟交汇点）**：两条道路相交但没有共用节点（如高架跨过街道）时，以俯视交点为虚拟路口：从鼠标指着的路段找离鼠标 60 米内最近的不相连交叉，两边各收集与对方相交的平行路段（双幅的两幅），每条在交点处切成两半交给同一个匹配器（`CrossingReader` / `JunctionReader.ReadCrossing`）。两条道路保持原高度（不用面板基层），立交范围内两条道路所在的两层（被替换高架的高度和下层道路的高度）都清理，原有道路在范围外的部分按原高度接回（高度容差 3 米）
- **虚拟丁字路口（宽容处理）**：一条路在另一条路旁边结束、不相连（如地面道路停在高架下方，尽头离中心线 30 米内、方向大致垂直），或只伸过对方一点点（30 米内）就到头，都按丁字路口匹配（`JunctionReader.ReadTee`）。十字和丁字都在虚拟交汇点周围按方向和高度（3 米内）收集两条道路的路段（`CollectAt`），双幅的两幅不要求都与对方相交；只对齐一条道路放 T 型时，支路放在鼠标所在的一侧
- **太短的保留部分**：原有道路保留下来的部分比路宽还短时（游戏会报“形状无效”），如果另一端是普通路中节点，就把下一段也拆掉、从臂端直接重建到下一段的另一端；打开调试日志时每段保留部分都会记录长度和接法
- **基层跟随已有道路**：对准已有路口/道路时，基层默认取已有道路的实际离地高度（不一定是地面，路堤、下沉、高架都可以），面板可切换为“手动”；跟随时总是原路口改造（替换原有道路），手动把基层放到高架/隧道段时才是叠建
- **T 型路口**：三条臂中最接近相反的两条配成直行主线（不论车道多少），剩下的是支路；支路角度 0~360°（小于 180° 在主线方向右侧）
- 鼠标指着已有道路 → 从最近节点出发，把 60 米内由短路段相连的节点算作同一个路口（双幅相交时一个路口有多个节点）→ 每条离开路口的路段记下方向、道路、单行方向、离地高度
- 方向相近（±15°）的路段归为一条臂：一条双向路段 = 双向臂；两条对向单行路段 = 双幅臂（量出分隔带）；相反方向的两条臂配成一条道路；主线取每方向车道多的
- 四向路口：中心、方向、两条道路及形式全部跟随路口；**指着普通道路**（两个方向）：只让主线对齐这条路（指着双幅的一幅时按面板分隔带推算另一幅），被交道路和夹角按面板；三向路口：提示三向立交尚未实现
- **原路口改造**（基层不是高架桥或隧道）：立交范围 = 所有生成路段中心线的凸包外扩 2 m。范围内、离基层高度 4.5 m 以内的原有道路（不含建筑自带的道路）在预览中显示为拆除；它们在范围外的部分重新生成，原节点那端接回原路网；臂端在原有道路上的投影离切断点 8 m 内、离中心线 4 m 内、高度差 3 m 内时，在投影处重新切并从臂端开始、接回立交；臂端不在原有道路高度（如高架的上层）时先加一段两端水平的坡道（长度 ≈ 1.5 × 高差 ÷ 最大坡度）升降到原有道路高度，接不上时再后退 10 m 避开臂端节点和立柱。和立交一起确认，可撤销。叠层（基层是高架桥或隧道）直接建设，可能出现重叠警告

### 6. 双幅道路（F6c）
- **几何**：一条双幅道路 = 两条单行道路，分别在中心线两侧偏移（分隔带宽度 + 道路宽度）/ 2。右侧通行时，沿臂 2→臂 0 行驶的那幅在右侧；左侧通行时镜像。单行道路的通行方向就是曲线方向，所以每幅路段都按行驶方向绘制。
- **匝道接主线**：匝道从**本幅**的节点分出、汇入本幅，是真正的分流/合流（单行道路一分为二），不再和双向道路形成平交路口。
- **匝道接被交道路**：被交道路也是双幅时，驶出匝道在近侧那幅形成路口（右转），再用一小段单行道路穿过分隔带接到远侧那幅（左转）；驶入匝道反过来。
- **车道数**：每方向车道数 = 那条单行道路的车道数，不必从双向道路里拆分方向。
- **节点规则不变**：共享节点的端点仍必须由同一个局部点得到，生成层测试额外检查每幅路段首尾相接且方向一致。

### 7. 匝道匹配规则（F6b）
- **车道数**：主线每方向 N 条车道（双幅时就是单幅的车道数），在分流点分为「直行 T 条 + 驶出 R 条」，匝道车道数 = R。
  默认 R = max(1, ⌊N/2⌋)，例如主线每方向 4 车道 → 2 条直行，2 条进匝道，匝道到被交道路路口再分成 1 条左转、1 条右转。R 可在面板里调整。
- **道路类型**：主线是公路（`RoadPrefab.m_HighwayRules`）→ 匝道从单行公路中选；主线是街道 → 从单行街道中选；选车道数最接近 R 的那条。
- **数据来源**（已在游戏内验证）：是否为公路读 `RoadData` 的 `UseHighwayRules`；是否单行读 `DefaultIsForward/Backward`。车道数：道路预制体上没有现成车道列表（`DefaultNetLane` 只挂在管线/电线/水道上），按游戏 `NetInitializeSystem` 的做法用 `NetCompositionHelpers` 现算默认截面的车道，见 `RoadCatalogBuilder`。
- **最近使用**：监听工具系统的“选中预制体变化”事件记录最近使用的道路，保存在设置里。

### 8. 臂端适配外部道路（F8b）
- **读取**：方向匹配（阶段 3c）时，除了读每条外部道路的角度，还读它在该方向上的形式：一条双向道路，还是两条对向单行道路（双幅）。双幅时同时得到两幅的间距，作为分隔带宽度。
- **连接节点**：每条臂的末端按外部形式输出连接节点：双向 1 个（在道路中心线上），双幅 2 个（每幅一个，方向与外部那幅一致）。自动连接时把这些节点的 `CoursePos.m_Entity` 设为外部道路的节点。
- **过渡段**：立交内部的道路形式可以和外部不同，例如外部是双向道路、立交内为了匝道分合流用双幅。在臂端引道上生成过渡段：
  - 双向 → 双幅：一个节点分成两条单行道路，逐渐张开到分隔带宽度；
  - 双幅 → 双向：两条单行道路逐渐收拢，汇成一个节点。
  过渡段长度按张开宽度和最大偏转角计算，属于生成层，可单元测试。
- **默认**：立交内部形式跟随外部（不过渡），只有在用户选择或立交类型需要时才分裂/合并。


### 8b. 与 Anarchy（无视碰撞）模组联动
- 不引用 Anarchy 的程序集：运行时在已加载的程序集里找 `Anarchy.Bridge.AnarchyBridge`，工具启动时调用它公开的 `TryAddToolSystem(tool)` 把本工具加入 Anarchy 的工具列表（开启 Anarchy 时它会移除本工具预览上的大部分错误）
- 面板只在装了 Anarchy 时显示开关，用 Anarchy 自己的图标 `coui://uil/Colored/Anarchy.svg`；开关直接用 Anarchy 的 UI 绑定（组 `Anarchy`：值 `AnarchyEnabled`、触发 `AnarchyToggled`），与它的工具栏按钮同步
- 开启时错误区顶部显示红色警告：游戏不再检查重叠、净空、坡度等，可能穿模、立柱压路、交通异常并留在存档里
- ✅ 游戏内验证正常（Anarchy 74604_40）

### 9. 默认不强制连接
臂端点的 `CoursePos.m_Entity` 留空（不连任何节点），引道末端与已有道路留出间距。后期的「自动连接」选项把它设为已有节点。

### 10. 中式快速路节点（`ExpresswayNodeTemplate`）
- 横向布置（从主线中心向外）：主线一幅 ±om → 匝道升降段 ±cl → 辅路 ±og。cl = om + 主线半宽 + 匝道半宽 + 间距，og = cl + 辅路半宽 + 匝道半宽 + 间距，所以匝道夹在高架和辅路之间，不压任何道路和立柱
- 沿主线：落地点在辅路与被交道路平交口之前 `RampTerminalOffset`（斜交时按辅路上的交点算）；升降段长度 = max(高差 ÷ 坡度上限, 匝道长度 − 两段横移)
- 地面路口在被交道路上是 2 个节点（每幅辅路一个），游戏里是两组信号灯；以后可由独立的“成组信号控制”mod 解决
- **主线两端落地**：原路口改造时外部道路比高架主线低（原有道路在地面）：主线在最外匝道节点之后 20 米开始用平滑坡道（≈ 1.5 × 高差 ÷ 坡度上限）降到外部高度，再延伸接外部道路，外部是双向道路时双幅收拢成双向；辅路不并回主线，延伸到同一位置后结束，留给玩家自行连接（游戏内反馈）。外部道路本身是高架时（对齐已有高架或立体交叉）主线保持原高度，不落地
- **对齐已有高架**：只对齐一条高架道路时，主线保持这条高架的高度，下层（被交道路、辅路）在地面；双幅道路的分隔带按对向那一幅实测（`JunctionReader.MeasureDualMedian`）；改造时新立交两层的高度都清理
- 升降段俯视为直线、竖向两端水平（`Bezier3.SmoothSlope`），和前后水平段衔接没有竖向折角；长度按 1.5 × 高差 ÷ 坡度上限
- 匝道间距（`RampSideGap`，面板“高级 → 匝道间距”，默认 1 m）同时用于匝道—主线、匝道—辅路，越小占地越窄。分隔带和匝道间距可按米或游戏网格的格数调节（1 格 = 8 米，按 0.25 格步进，和游戏平行道路工具一致）
- **车道平衡**（菱形和快速路节点通用，面板可关）：主线在下匝道分出点和上匝道汇入点之间改用“主线车道 − 匝道车道”的单行道路；快速路节点的辅路在落地点和上匝道分出点之间改用“辅路车道 + 匝道车道”的单行道路。只在目录里有车道数正好的道路时生效。宽度变化时按不变车道一侧对齐（主线保持内侧、辅路保持外侧边缘），中段中心线平移半个宽度差；在分流/汇入节点处用游戏道路工具“边缘对齐”同样的做法：节点仍是共用的点（`CoursePos.m_Position`），路段曲线端点横向偏移（道路不是 StrictNodes，路面取曲线自身端点），所以路面从节点处就对齐，不需要 S 形平移（早期 S 形平移会在节点外出现收腰）。公路宽度随车道数变化，奇偶车道数居中会错开半条车道，边缘对齐正好解决；普通单行道路 1–3 车道同宽，偏移为 0；以后所有立交都按这个规则

### 11. 单点立交（`SinglePointTemplate`）
- 每条匝道：主线高度横移（与主线相切）→ 俯视直线升降（两端水平）→ 地面转弯段进出中心节点。转弯段在中心节点处沿“主线方向与被交道路方向的角平分线”，两条切线在横向 cl 处相交、切线等长，只朝一个方向弯
- 主线节点立柱：宽道路（≥10 米，游戏内为 Horizontal Pillar 12/20）是门式——横梁在头顶、两条腿在桥面边缘以内，中间可以过车；窄道路是中心一根。腿中心离匝道中心线不到“匝道半宽 + 腿半宽 1.5 + 0.5 米”算撞上（游戏内实测：只按中心一根柱算时匝道撞上原道路同款立柱的腿）
- 地面转弯段：半径 30 米圆弧 + 沿角平分线的直线进出中心节点；圆弧在桥面立柱腿范围之外转完（升降段横向位置取 max(Cl, 桥面外缘 + 圆弧横向落差)），桥下只有直线斜穿，占用主线的长度最短
- 桥下有好几处占地（被交道路、每条匝道各一段），立柱放在它们之间的空隙里（`PillarPlanner.PlanNodes`：第一处之前、最后一处之后各一个节点，每个空隙可放一个，切分节点和中部立柱都检查），不再受单跨约 80 米的限制。相交角度 55°–125°：中心节点处匝道与被交道路的夹角是所在扇区的一半，55°（125°）为游戏内实测极限
- 被交道路在立交内必须是双向道路（双幅时中心会变成两个节点）：外部是双幅时立交内自动换成车道数相同的双向道路，两端用 S 形拆回双幅接上原有道路（部分苜蓿叶同样处理）

## 架构

```
UI 层 (React/TS, 官方 UI 模板)          方向数、类型、每层海拔、每臂道路
        │  ValueBinding / TriggerBinding
工具层 (C#, 游戏 API)                   InterchangeToolSystem：整体预览、旋转、方向匹配、放置
        │                               InterchangeUISystem
生成层 (纯 C#, 不依赖游戏)              IInterchangeTemplate(Legs, Levels) → List<RoadSegmentSpec>
        │                               几何：贝塞尔、圆弧、坡度、净空
落地层 (C#/ECS)                         NetCourseBuilder：逐点采样地形，写 CreationDefinition + NetCourse
                                        PrefabResolver（含地下预制体切换）/ JunctionReader（读路口方向）
```

**核心原理**：游戏的道路工具通过创建 `CreationDefinition + NetCourse` 实体（贝塞尔曲线 + 高度）造路，之后由游戏自己生成路段、桥墩、费用和冲突检测。本 mod 只负责**算出每条道路和匝道的曲线**。

**节点合并规则**（从 `GenerateNodesSystem` 确认）：同一帧的定义实体中，端点世界坐标**完全相等**才会接到同一节点。所以共享节点的路段必须由同一个局部点经同样的计算得到（见 `InterchangePlacer.ToWorld`），生成层测试也用精确相等检查。

**预览/确认规则**（阶段 1 踩坑后确认）：预览变化的帧 `applyMode = Clear`（游戏清掉旧临时道路），不变的帧 `None`，确认的帧 `Apply`。
