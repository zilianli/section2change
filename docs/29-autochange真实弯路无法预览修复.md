# autochange 真实弯路无法预览修复

日期：2026-10-31。分支 `autochange`，版本 `0.0.1-beta`。节点模式仍仅生成临时预览，正式放置未开放。

## 结论与原因

这次使用用户再次测试后日志中的 **8 个端点、完整原路贝塞尔控制点、实体版本及实际切线**回放。修复前，定向和涡轮都在外部接路检查被拒绝，没有进入完整网络候选检查。

有两处原因：

1. 旧接路检查把“整条外部连接的直线方向与两端切线均相差不超过20°”当成必要条件。当前道路能平滑弯曲接入，但第二臂的最佳整体偏角仍约28°／35°，因此提前被拒。
2. 内部布局的轴线和中心只从原选点处的切线估算。弯路向外退接后偏离这些无限延长的切线；默认16%涡轮的原参考布局需要约47°的整体横移。单纯增加切点组合或缩短控制柄不足以适配。

## 修改

- 根据两端真实切线生成连续曲线。20°改为认证每个输出道路段的实际水平切线相对该段弦的偏角：三个导数控制向量均位于同一个前向凸锥内，因此整段切线都受约束。道路与原端点及核心接点保持相切。
- 横移较大时使用较短控制柄，减少双幅道路在S弯中部互相挤压；仍由完整网络净空检查决定是否可接受。
- 同时认证曲线及最终切片对核心主线方向严格向前，保证接路不折回核心区域；保留10米最短道路段、70米最长输出段和128段预算。曲线和切片均重新检查严格纵坡。
- 保留原切线参考，再增加“相对两臂中心连线及交点”参考。两种参考均重新求解完整内部布局，不缩放道路。每种参考仍有定向右出右进8组、左出左进11组、涡轮6组的有限参数备选。
- 全部参考和切点组合共享128次完整网络检查。对完全相同的核心几何去重，避免参考重合时重复花费候选预算。每个候选仍须通过8.5米道路净空与支撑检查。
- 保留原节点身份、原路位置、断面、切点及切线；不擅自扩大用户设定的退接上限。
