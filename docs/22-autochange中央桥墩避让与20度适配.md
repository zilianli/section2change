# 中央桥墩避让与20°端部适配

2026-10-30，`autochange`，版本维持 `0.0.1-beta`，正式放置仍锁定。

## 本轮问题

用户在16%和27%坡度预览中均遇到 `OverlapExisting: Vertical Pillar`，并要求水平端部偏角从15°扩展到20°。约15:23和15:24的日志中，四个新建立柱位于上层中央跨线段的中间位置。上层中央段约95～120米，道路高架分段上限80米；游戏自动等分新增节点和支柱，落在下层道路上。路面高差够用并不能保证这些支柱避开道路。

新增回归在旧逻辑上复现16%和27%的门架碰撞，20°边界亦先失败，再实现修复。

## 新的规划与检查

沿用 section2change 的 `PillarPlanner.PlanNodes` 和 `InnerPillars` 规则，读取各幅道路的高架分段上限、中部立柱间距和实际道路宽度，主动规划较高中央跨线段的支点。为四幅道路都提供规则，避免用单一中心地形采样误判“该段不会有桥墩”；地下或地面段可能因此被保守多分段。

先按下层两幅道路轴线与全宽投影生成禁放区，门架采用整幅道路宽度及3米厚度的保守几何模型。已有起终点可以继续充当支点，距它们过近的冗余计划节点不插入。新增节点间距仍至少为 `max(10米,道路宽度)`，当前20米宽道路保持20米。

优先保留3米附加余量，安排不下时尝试2米余量。每次都重新列出既有端点、新增端点、最终各段的游戏自动切分立柱和中部立柱，用真实横向门架胶囊对可能处于其下的所有主线/匝道实际曲线检查；只有 `Clear` 才接受，`Uncertain` 也拒绝。因此降低的是附加余量，未跳过实体包络或最小节点间距检查。

若首组支点被匝道挡住，继续使用2米网格、最多256节点的有界搜索；每条候选边检查其所有自动/中部立柱，备用方案另保留1米实体净空。仍无法安排则拒绝该布局并继续搜索半径和退接，不隐藏游戏警告。搜索网格可能保守漏掉很窄的可行区域，不表示数学上绝对无解。

端部朝向限制已统一为20°，保留真实端点切线、三维纵坡检查、道路实际宽度检查和原有车道平衡。面板错误提示同步更新，桥墩失败数和原因写入搜索日志；游戏错误定位增加对象位置、父Owner链和网络节点位置，便于继续追踪实际自动支点。
