# 定向与涡轮节点预览实施计划

用户已通过苜蓿叶两种样式及高坡度修复的游戏测试，授权按docs/15顺序继续其他类型。本阶段先完成定向和涡轮可部署预览，再按原顺序推进三向及平交类。沿用autochange / 0.0.1-beta，正式放置继续锁定，不提交发布。

## 实现方法

1. 复用section2change已有StackTemplate及其turbine模式内部匝道算法，按所选端点实际道路宽度、分隔带、交角、交通侧、车道平衡、桥墩参数和最大坡度重新生成内部核心；不缩放既有坐标成品。
2. 核心在所选端点拟合的世界参考系中重新计算。贯通家族高低层颠倒时交换内部家族映射，外部道路和真实端点仍保持原编号、流向和世界高程。LHT通过刚性镜像参考系及明确的端口映射处理，必须验证12种有向通行关系。
3. 端点外沿真实原路有界退接，新增独立的平滑接路段，精确保留新截点的高程、切线、路型及已有节点绑定；预留空间不足继续退接，不强行接入。
4. 类型无关的3D路面检查允许分层交叉，仅对同一路径和精确共节点的规定终端段作局部处理，拒绝未分层或未证明净空的交叉。新增接路也检查，不直接套用苜蓿叶“所有匝道平面分离”的假设。
5. 继承内部求解的桥墩规划并复核外部接路与自动/中部支持点，失败明确诊断；真实地形和游戏生成桥墩仍需游戏验证。双向单幅和单双幅混合转换本阶段仍不开放，差异路型明确拒绝。
6. 定向提供右进右出/左进左出，减车道道路采用精确车道匹配，左出左进保持外侧直行边缘；涡轮按自身出入口次序处理。核心模型携带独立路径ID及正确预制体宽度。

## 验证与交付

- 独立单元测试先失败再实现：RHT/LHT、12种动作、两个主路家族高低层交换、左右进出、实际车道平衡、错误输入及有限退接预算。
- 集成日志端点及合成真实续路，覆盖短预留空间、混合高程、20°内端部方向和精确节点/切线。
- 核验分层交叉可通过，同层交叉、支柱冲突及不安全/不确定几何会拒绝；不压制游戏错误。
- 独立静态复核、相关测试、完整生成层回归及Release构建。游戏正常退出后备份、部署并逐文件核验。用户在复制存档中比较定向两种进出方式和涡轮，再继续下一阶段。
