# autochange 既有类型输入契约扩展

**Goal:** 将 section2change 的 13 个既有类型纳入节点模式请求，扩展三向输入、道路形式和通行动作验收。

**Architecture:** 复用 InterchangeType，建立只读类型契约；EndpointConstraints 保持四向旧接口，增加按类型校验的重载。请求冻结输入、交通侧、各臂允许延伸距离及最大坡度，显式区分输入就绪和可放置。

**Tech Stack:** C#、netstandard2.0、xUnit。

用户已授权继续开发；直接执行，不提交、不发布、不部署。延续整体几何求解方案，不通过缩放旧模板实现适配。

- [x] 从既有模板验证 13 种类型及臂数，定义四向、T 型、Y 型三种契约。
- [x] 先写测试：13 类型分别接受双向、双幅、混合有效端点；错误臂数、重复实体和 T 型贯通车道不符拒绝；Y 型不错误套用相对臂规则。
- [x] 验证测试缺少 API 而失败，实现契约和通用请求。
- [x] 每种四向需求包含 12 个非掉头动作，三向包含 6 个；动作需求不等于内部拓扑或游戏车道已建立。
- [x] 请求冻结原始数组；参数不能超过 30%，不接受无穷延伸；类型已登记不意味着几何已支持。
- [x] 运行针对测试及完整生成层回归，更新阶段范围。

后续按苜蓿叶、定向/涡轮、三向全互通、含平交的类型逐组实现各自内部拓扑和几何。每组仍需全路网净空、原路拆改、预览与游戏测试；本任务不把只有输入契约的类型标记为可放置。

补充：三向参考中心重载与原四向接口共存；5 个三向类型含大坐标/输入乱序测试。独立静态复核发现极限坐标会导致投影转 float 溢出，新增用例先复现失败，随后拦截距离和 RMS 的不可表示结果。相关定向测试 67 项通过，复核确认该问题关闭。
