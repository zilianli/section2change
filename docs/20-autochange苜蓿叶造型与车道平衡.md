## 本轮起点

用户已在原场景验证上一包的 16% / 19% 预览均正常且无叠放。本轮针对截图中的直连匝道形态、分合流边缘和车道平衡继续优化；上一包的验证不自动代表本轮新道路断面也已经通过游戏验证。

## 与 section2change 对齐的规则

参考 `Templates/CloverleafTemplate.cs` 的 `Road.Drop`、`Road.Shift`、`AddLine` 及小端弧/大中弧布局，保留独立端点求解器和真实道路退接。

四幅道路分别选择少掉匝道车道数的同类正向单行道路。示例：四车道主线接单车道匝道，驶出后至环道汇入前为三车道；环道汇入到环道驶出之间的中央交织段恢复四车道；环道驶出后到直连匝道汇入前再次三车道。每幅有两段减车道，共八段。找不到精确车道数匹配时保留全宽并提示，不拿近似车道数替代。

减车道段中心向分隔带移动半个宽度差，内缘保持原位置。匝道曲线在逻辑连接点处向外移动半个“全宽减匝道宽度”的差，使匝道外缘与原道路外缘对齐。曲线端点和逻辑连接节点分别传给 NetCourse；节点仍使用原主线节点坐标，防止视觉外移变成断路。

直连匝道将斜直过渡改为短端部圆弧与大半径中间圆弧，保持切线连续、分合流首末平坡、最小路段长度及坡度上限。空间检查使用实际断面宽度与实际路面曲线；局部分合流豁免根据逻辑节点匹配，其余冲突仍拒绝。

独立复核发现原搜索半径范围对 70° / 75° 斜交不足，已补充较大的端弧与中弧候选。搜索分两阶段，先检查原紧凑范围，再扩展范围；为扩展阶段保留四分之一预算，防止退接上限提高到 1000 米后挤掉已存在的零退接解。总预算仍为 2048 次；预算耗尽明确报告，不等同于无解。

## 玩家测试重点

1. 原场景相同八个端点，先 19% 后 16%，自动层高、退接上限 500 米。
2. 看外侧直连匝道是否成为圆润曲线，分合流是否沿外侧车道接入，是否新增红线或形状无效。
3. 每幅道路应出现“全宽 → 减车道 → 中央全宽 → 减车道 → 全宽”；以四车道加单车道匝道为例，应为 4→3→4→3→4。外部原路仍为四车道。
4. 检查四个象限的环道、直连匝道及桥墩，特别是道路断面变化的节点。若异常，固定预览停留约 5 秒并反馈截图，保留日志。
