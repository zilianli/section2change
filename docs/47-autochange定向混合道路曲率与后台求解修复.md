# autochange 定向双向／混合道路修复

分支 autochange，版本保持 0.0.1-beta。用户已确认苜蓿叶全双向、混合、混合弯路的预览成功；这些反馈不代表放置、交通或其余类型均已通过。

## 问题与证据

2026-11-03 游戏日志快照保存于 `.artifacts/autochange/stack-real-20261103/InterchangeMod.Mod.log`。全双向定向的同步求解在游戏中耗时约35.2秒，混合弯路失败前约50.3秒。两者在游戏更新线程内计算，确实可能造成明显卡顿。

测试保留四条全双向原路以及六条混合弯路的实际 Bezier、节点/边身份与版本。目录元数据中的部分桥墩包络为测试假设，不能视为完整游戏存档重放。成功的混合直线场景未保存实际原路曲线；新增测试只采用日志姿态，明确构造900米直线延伸。

混合弯路的数学核心本已成功，但外切口650米处只余约18.6米尾段，不足原32米宽道路的节点空间。旧处理只往外寻找安全切口，遇道路尽头后拒绝整个核心；继续更大预留又导致支持物冲突。这属于切口窗口过窄，并非该空间整体放不下立交。

右转的旧模板连续横移采用多段圆弧，弧段间存在明显曲率突变。尝试直接改为整条大弧线时，完整检查发现与左转匝道冲突，因此未采用该捷径。

混合直线截图的工具提示实际包含 InvalidShape。中心线证书不能唯一解释原生网格错误，当前日志也未保存对应原生面片，故不能宣称已从日志证明所有叠放均已消除。

## 实现

1. 定向双向／混合求解使用单个后台任务，至多保留一个最新替代输入。ECS、地形、原路读取和临时实体提交仍在主线程。参数、端点、模式和工具生命周期变化会取消旧修订；完成后重新核对完整原路曲线与版本、道路目录及地形，陈旧结果不进入预览。
2. 取消信号贯通核心枚举、真实转换、顺势优化和最终认证。复核发现的“核心成功后取消仍继续转换”已用确定性测试先复现，再修复。取消和销毁不阻塞游戏线程等待任务退出。
3. 混合定向保留第一个已认证核心，避免为外部接路评分再消耗大量核心拟合。最终真实道路仍重新认证，不以数学代理代替实际切口。
4. 保留既有核心，在预留外接段的有效长度内，以5米步进尝试更近的切口。下界包含原生干线、最小首跨与转换扇形所需长度；候选仍须通过宽度安全尾段、真实弧长上限、转换几何及全网检查。
5. 右转采用非均匀参数夹持 C2 水平样条。所有接口、逻辑节点、桥墩节点位置、原 Y 控制点、首末接口手柄及道路元数据保持。最多增加四个计入共享预算的全网候选；坡度、半径、控制方向、三维弧长上界、净空、桥墩任一项失败就保留已有方案。必要的横移空间仍保留。
6. 读取错误 Icon 时不再以另一命令缓冲生成的 Error 查询非空为前提。定向节点模式自动记录预览修订和错误来源；面板已有阻止错误时不再同时显示“等待游戏检查”。确认仍由原生 GetAllowApply 决定。

## 验证

- 两组真实来源曲线的本机回放从约21.2／29.4秒降至约1.1／1.5秒，并均获得几何证书。上述为本机离线测量，不承诺游戏内相同耗时。
- 八条右转重拟合均通过全网检查，匝道段间最大曲率跳变约0.0000015至0.0000054每米，原值约0.04每米。独立比较确认两组接口、节点、原高程和元数据保持，右转三维控制多边形最大约73.05米，小于80米桥跨上限。必要的横移外形仍保留，实机外观由玩家复测确认。
- 169项相关类型／混合道路／左右行／预算测试通过；最终真实与构造场景、取消及调度11项通过。旧入口兼容性复核23项通过；最终完整回归2319/2319通过，0失败、0跳过、0错误、0中止，耗时11分32秒。
- Release构建0错误，保留 StackTemplate.cs:698 的1项原有可空性警告；UI类型检查通过。独立复核发现的一项取消P2已关闭，复核未发现剩余P1/P2。
- 首次全量回归发现旧环岛平滑入口的反射调用参数兼容性退回，已保留原命名及参数数量，以独立名称实现可取消入口。失败的首次运行已中断并留存，不计为通过；修复后重新验证旧入口并重跑构建与全量回归。

## 玩家复测

先用原来的16%坡度、每臂1000米上限，按原来节点重新生成定向预览：

1. 全双向：比较右转横移／汇入曲率，确认不再明显折曲；查看原生错误。
2. 混合直线：检查原来的无效形状／叠放是否仍出现；若仍有错误，固定预览停留约5秒，让自动诊断记录来源。
3. 混合弯路：检查能否生成、操作面板是否仍长时间冻结、切口和尾段是否自然。
4. 求解期间改变参数或退回菜单，确认旧方案不会突然出现；随后重新生成。

在测试存档确认放置后，再检查车道连接、断路、各方向交通及保存读取。该轮发布前必须区分离线证书和实机反馈。
