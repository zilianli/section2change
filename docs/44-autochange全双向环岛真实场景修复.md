# 全双向环岛真实场景修复

分支 `autochange`，版本保持 `0.0.1-beta`。本轮来自2026-11-02玩家“全双向环岛无法预览”的截图及游戏日志；上一包数学测试通过不能替代此场景的实际预览验收。

## 复现与原因

日志记录四个实际双向端点，均为 `XL Road Divided`，每方向4车道、宽40米；两组高程约488.632和478.632米，坡度设置16%、退接上限1000米。面板提示“道路或参数数据已变化”，日志实际在搜索开始前返回 `InvalidInput`，尝试次数为0。

1. 原路中部一处相连曲线端点相距约0.0500499米，刚超出原有0.05米连续性阈值。这种世界坐标约数千米处的浮点表示余量没有被考虑，导致整条原路被拒绝。
2. 修复连续性后，真实分段路廊回放暴露双向转换尾段问题：核心按虚拟单向路得到的切点，加上转换预留长度后，有时落在真实道路小段的末尾。例如630米处不足10米尾段，705米处仅余11米，无法满足40米宽原路的尾段要求。
3. 实际道路目录还含有19米宽的 `ExtradosedBridge04` 和港口道路。原转换按“最窄准确车道”会误选专用桥梁，尽管有普通24米宽 `Medium Road Oneway`。该桥梁目录跨度448米、中柱宽约56.1米，不应被普通转换或环道自动选用。

原始日志及无损曲线摘录保存在 `.artifacts/autochange/twoway-roundabout-20261102/`；四条曲线成为嵌入测试夹具 `Fixtures/twoway-roundabout-20261102.json`。

## 修复

- 原有5厘米连续性标准增加与浮点坐标尺度对应的表示余量，距离运算使用double。没有吸附、平移或改写真实控制点；明显断开仍拒绝。确认快照仍逐值精确比较，1毫米真实变化仍会使旧快照失效。
- 仅双向转换的外侧真实切点可以继续沿同一条原路向外移动，优先在下一段内退入10米、否则检查现有节点边界；虚拟核心接口不动。真实距离写回结果、界面、来源绑定及确认重切。继续受玩家上限、原路末端前10米及保守弧长检查约束。原双幅臂不使用此调整。
- 复用项目既有 `RampMatcher.IsOrdinaryRoad` 规则。普通自动转换、环道、减车道和集散道路不使用专用桥梁、港口等资产。显式原路只影响对应断面查找和相对贯通匹配；手选匝道只在匝道用途保留，不能泄漏到其它自动用途。
- 环岛、井字、Y型的道路准备和减车道选择器提供默认关闭的普通自动候选策略，只在混合路径开启。减车道仍从完整目录查找显式原路，仅过滤派生候选；原全双幅调用保留原策略。所有最终使用道路仍按真实预制体元数据复核，未屏蔽游戏原生错误。
