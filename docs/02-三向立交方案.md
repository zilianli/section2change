# 三向（T 型）立交方案：快速路 T 型节点 + 喇叭形

> 状态：方案已确认（2026-10-24）；4a 已实现并验证（T 型路口匹配、基层跟随已有道路）；4b 已实现并验证（快速路 T 型，`ExpresswayNodeTemplate(tee: true)`）；4c 已实现（喇叭形，`TrumpetTemplate`），待游戏内验证。分三步做，每步都先在单元测试和 SVG 预览里定型，再进游戏验证，验证通过后做一次 git 提交。

## 已确认的选择

| 问题 | 选择 |
|---|---|
| 快速路 T 型节点：支路怎么接辅路 | 支路从高架下穿过，与两侧辅路各形成一个 T 字路口（支路上 2 个节点），远侧车辆也能直接左转进支路 |
| 喇叭形：环形匝道用在哪个方向 | 面板可选；默认“驶出主线用环道”（主线左转进支路走 270° 环道，支路左转进主线走跨线桥的半定向匝道） |
| 喇叭形：分层 | 主线在基层（默认跟随已有主线的实际高度，不一定是地面），只有半定向匝道用一座跨线桥跨过主线；沿用“基层 + 层间高差” |

## 4a 三向基础（两种 T 型共用）

1. **三臂模型**：臂 0 / 臂 2 是直行的主线，臂 1 是支路（T 的竖笔）。`InterchangeParams.TLegs(角度, 支路在左/右)` 生成三条臂，支路夹角 60°–120°（与十字一样按游戏内实测再调）。
2. **路口匹配**：`JunctionMatcher` 现在遇到三向路口会报“尚未实现”。改为：两条相对的臂配成主线，剩下那条是支路，读出支路在主线的哪一侧、夹角、道路形式（双向/双幅）。立体交叉（虚拟交汇点）只在两条路真正相交时成立，T 型不需要。
3. **面板**：立交类型多出“快速路 T 型”“喇叭形”；空地放置时多一个“支路方向：左 / 右”（也可以用一个镜像快捷键切换）；对准已有 T 型路口时自动决定。
4. **改造与接回**：沿用现有的拆除 + 接回逻辑（范围凸包、边缘对齐、臂端坡道），三条臂各自接回。
5. **基层高度跟随已有道路（所有立交类型通用）**：基层不一定在地面。对准已有路口或道路时，基层默认取匹配到的已有道路的实际离地高度（路堤、下沉、高架都可以；各条道路高度不同时，主线取主线的、支路取支路的，与立体交叉现在的做法一致）。面板显示“基层：跟随已有道路 X m”，可以切换为“手动”按面板数值放置；空地放置时仍按面板的基层。分层规则（自动高差、高架/路堤/隧道分段）都以这个基层为起点。

## 4b 快速路 T 型节点（`ExpresswayTTemplate`）

在现有中式快速路节点（十字）的基础上去掉一侧的被交道路：

```
  辅路远侧 --------+--------
  =================|=================  高架主线（双幅）
  =================|=================
  辅路近侧 --------+--------
                   |
                 支路（地面，从高架下穿过）
```

- 主线高架直行；两侧地面辅路；四条匝道和十字版完全一样（路口前落地、路口后爬升，外切曲线、车道平衡、边缘对齐）。
- 支路从近侧伸入，与近侧辅路形成 T 字路口，继续从高架下穿过，在远侧辅路处结束，形成第二个 T 字路口。
- 立柱：主线跨越段只需避开支路（复用现有的立柱规划）。
- 远侧辅路在支路处断开成两段，接在 T 字路口上；支路不再往外延伸。

## 4c 喇叭形（`TrumpetTemplate`）

全互通、无信号灯的三向立交，用于公路接公路，或公路接一条主要道路。

功能组成（默认“驶出主线用环道”，右侧通行，支路在主线一侧）：

| 转向 | 匝道 | 形状 |
|---|---|---|
| 支路 → 主线（右转） | 直连匝道 | 外切曲线分出/汇入 |
| 主线 → 支路（右转） | 直连匝道 | 外切曲线 |
| 主线 → 支路（左转） | **环形匝道** | 270° 内切圆弧，半径可调（默认按匝道道路的最小转弯半径） |
| 支路 → 主线（左转） | **半定向匝道** | 上跨主线的跨线桥（唯一一座桥） |

- 支路是双幅：两幅在“喇叭口”处分开，分别连接上面四条匝道。
- 面板选项：环道用于驶出还是驶入（两种喇叭的镜像布置），环道半径（30–150 米，默认 60），支路方向。

实现说明（与上面的初稿相比有调整）：

- 支路两幅都以跨线桥从上层跨过主线（不只是半定向匝道一座桥），主线留在基层；面板不再显示“上层道路”选项。
- 环道（主线远侧幅 → 支路）直接与远侧幅外切（圆弧切入主线，没有横移段），与主线并行重叠的起始段保持主线高度，之后右转 270° 升降到桥面高度，接到支路出向幅。
- 半定向匝道（支路进向一幅 → 主线远侧幅）：进向一幅到环道圆心高度后左转 180° 绕过环道（与环道同心，间距等于支路两幅的间距，像支路两幅一起掉头），沿环道西侧向下，再右转汇入远侧幅；边走边升降，最后一段与主线同高，不与环道交织、不与任何道路平交。
- 两条右转直连匝道在支路一侧（主线近侧幅），各是一段四分之一圆弧。
- “环道用于驶入”是上述布置沿主线方向镜像并把所有路段反向。
- 支路是双向道路时，立交内部改用同车道数、两幅并排放得进双向道路宽度的单行道路做双幅（街道单行道带人行道较宽，如 XL Road Divided 40 米而 Medium Road Oneway 24 米放不下，就用 20 米的公路单行 4 车道），分隔带取“双向道路宽 − 2 × 单幅宽”，两幅外缘正好对齐双向道路两侧边缘，外端两幅平行接到双向道路端点的同一个节点（边缘对齐，节点与曲线端点横向错开）。早期用 12° 斜向汇合，宽的双向道路（如 XL Road Divided）在汇合节点报“形状无效”（节点几何折叠）。单行道路比双向道路一半还宽时仍用斜向汇合。
- 对准“主线高架、支路在地面”的立体交叉时跟随原有高度：支路平着从高架下穿过，主线跨越段的节点按立柱规划避开支路；近侧直连匝道自己在圆弧上升降（两端与道路并行重叠部分保持水平）。
- 车道平衡：主线在匝道分出点和汇入点之间减车道，边缘对齐（同中式快速路）。匝道在主线一端平行接入：曲线端点在主线外侧 (主线宽 − 匝道宽)/2 处（匝道外缘对齐主线全宽外缘），与减车道后的主线并排接到同一个节点，不斜插主线中心。匝道间距（面板“匝道间距”）对喇叭形生效。
- 近侧支路从桥头起沿支路真实方向延伸（不再按正交布置），外端落在原有道路的中心线上，斜交时也能接回；直连匝道是同时与主线、支路相切的圆弧，半径可在面板手动设定（不能小于坡长约束给出的下限）。
- 主线在上层时，直连匝道先用较小半径（≤ 80 米）的圆弧离开高架主线，并行重叠段短于游戏切分高架路段的长度，避免切分点的立柱落在主线上。
- 占地：近侧直连匝道的半径主要由支路下桥的坡长决定（10 米高差、8% 时约 190 米），面板“最大坡度”可调（不超过道路自身上限），越陡越紧凑；环道半径默认 40 米。
- 相交角度 35°–145°：支路两侧都沿真实方向走直线，环道、半定向匝道、直连匝道都是同时与主线和支路相切的圆弧，转角随交角变化（环道 270° ± 偏角）；跨线桥立柱按每一幅的斜交位置规划。越斜，锐角一侧的直连匝道半径越大（8% 坡度时 90° 约 350 米、60° 约 700 米），环道也可能需要加大（面板会给出最小值）。
- 匝道与所接道路并行重叠那段再多保持同高 15 米才开始升降：游戏把重叠部分算进节点区，正好在重叠结束处分段时剩下的一小段会被判“坡度过陡”。接不上臂端的原有道路切断端再退“10 米 + 半路宽”，宽路斜穿出立交范围时端头两角不伸进来。
- 双向支路拆成双幅时两幅之间至少留 2 米（游戏画平行道路的最小间距 0.25 格）：两幅贴在一起（分隔带 0）游戏报重叠。
- 仅支持右侧通行。
- 跨线桥：沿用现有的分层、净空、立柱避让（立柱避开主线两幅），桥两端用平滑升降段（两端水平的竖曲线）。
- 车道平衡和边缘对齐规则照旧：主线在出口后减车道、入口后恢复，宽度变化时保持直行车道一侧对齐。
- 几何先用单元测试锁定：环道半径与切线连续、跨线桥净空、坡度、所有匝道端点接在节点上，然后用 SVG 预览检查形状。

## 十字路口当 T 型

三向立交（快速路 T 型、喇叭形）也能对准十字路口：支路取鼠标所在一侧的那条臂（鼠标移到主线另一侧就换边，预览随之重建），对面那条臂在立交范围内照常拆除，范围外保留的部分没有臂端可接，自由结束。面板匹配信息里会提示。

## 风险

- **喇叭口的节点**：支路两幅分开处，以及环道与直连匝道汇合处，都是匝道之间小角度分合，可能触发“形状无效”。处理办法和菱形一样：用足够长的外切曲线让节点延伸到道路不再重叠。
- **环道半径**：游戏对公路匝道有最小转弯半径。半径太小会报错，太大则占地很大，需要游戏内实测一个默认值。
- **T 型路口匹配**：已有道路的 T 型路口中，主线可能不完全直（两臂夹角不是 180°）。允许 ±20°，超出就提示无法匹配。
