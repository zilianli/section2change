# 弯道适配方案（阶段 7a）

决定（2026-10-26）：
- 只考虑直线和简单曲线，S 形不专门优化。
- 两条路（主线、被交道路）都可以是弯道。
- 方式：立交仍按直线生成，再**整体沿实际道路的中心线弯曲**（所有立交类型一次支持），不在每个模板里单独处理弯道主线。
- 弯道求解可能更慢：面板要提示玩家；某些形状放不下时直接提示玩家先把道路调整平直。

## 1. 读出道路中心线

- 第一版按“单段圆弧”读曲率（第一条路段两端切线转角 ÷ 长度），游戏内不行：曲线工具画的路是贝塞尔，不是圆弧——路口附近几乎是直的、往外才弯，按一个平均半径整体弯曲时立交两端对不上原有道路；“直线接弯道”这种常见道路也被当成前后对称的圆弧。所以改成直接追踪道路中心线。
- 追踪（`JunctionReader.Trace`）：从离开路口的路段出发往外取俯视点，到头的节点上接着走与当前方向最一致（30° 内）的道路路段，追 2000 米或到路的尽头（之后按最后的切线直线延伸）。普通路口每条离开的路段、立体交叉切开的两半都追（`ExternalEdge.Trace`）。
- 每条臂的中心线（`JunctionMatcher`）：取一幅的追踪点沿它自己的法向横移它在路口处离臂中心的横距（平行曲线，弯道上也准）；前面补上立交中心（路口内那一小段当直线）。匹配结果给四条：主线前 / 后、被交道路前 / 后（都按“从中心离开”的方向记），主线和被交道路对调时跟着换。
- 只对准一条道路（在路上放置）时，两条臂接成一条折线，中心取鼠标在它上面的最近点、主线方向取那里的切线，再从那里切成前后两条——弯道上放置时立交顺着实际的路摆。
- `Centerline`：从原点出发、按中心处离开的方向（路口匹配读出的路段切线，比从点估计准——从点估计会差半个弦角，R 500 米时 600 米外偏 6 米）转到沿 +Z，每 2 米重采样，给出弧长 s 处的位置和切线转角。
- 追踪出的中心线整条离起点切线不到 0.5 米的当直线（不能按半径判断：半径 3000 米的弯道在 700 米外已偏出 80 米，大型立交的臂端接不回原有道路）；立交范围（离中心 600 米）内最急处半径小于 150 米时报错，请玩家先把道路调整得平直一些。面板显示每条路两侧的最小半径。

## 2. 弯曲变换（生成层 `CurveWarp`，纯 C#、可单元测试）

立交局部坐标：中心 O，主线方向 ê_m，被交道路方向 ê_c（与主线成交角 θ），斜坐标 p = O + a·ê_m + b·ê_c。

- 中心线：A_m(a) 是主线中心线上离 O 弧长 a 的点（a > 0 用前方那条、a < 0 用后方那条），φ_m(a) 是那里切线相对中心处转过的角度；被交道路同理 A_c(b)、φ_c(b)。后方那条反过来走时切线反向、转角不变号。
- 沿主线弯：W_M(p) = A_m(a) + Rot(φ_m(a))·(b·ê_c)。主线中心线和与它平行的各幅（双幅、匝道并行段）都**精确**落在平行线上；被交道路的两幅会张开（不用它）。
- 沿被交道路弯：W_C(p) = A_c(b) + Rot(φ_c(b))·(a·ê_m)。对被交道路精确，主线两幅会张开（不用它）。
- 混合：W(p) = (1 − t)·W_M(p) + t·W_C(p)，t = smoothstep(0.1, 0.9, |b| / (|a| + |b|))——离主线近（|b| 小）用 W_M，离被交道路近（|a| 小）用 W_C（主线中心线上 t = 0、被交道路中心线上 t = 1，所以各自只需对自己那条路精确）。两条路的中心线和各自平行的各幅都精确；中心附近两者只差几十厘米；象限里的匝道被平滑拉伸 / 压缩（两条路都弯时这是必然的：两个弯道之间的距离和直线时不同）。两种弯法在象限里相差 κ·a·b 量级（离中心 200 多米时几十米），过渡窗口窄（0.35–0.65）时象限里的苜蓿叶环道被压短一半、坡度翻倍，所以窗口取 0.1–0.9（过渡铺满大半个象限）；代价是离中心 150 米内、横距 25 米左右的匝道偏离平行线约 1–2 米，各幅（横距 10 多米）仍在厘米级。
- 只有一条路弯时（另一条是直线）同一公式退化为：弯的那条精确、直的那条保持直线不张开。
- 路段：端点和节点按 W 变换（同一个局部点得到同一个结果，节点照样合并）；两头切线方向按端点处的雅可比矩阵（数值差分）变换，前后路段在共用节点处仍相切；两个控制柄长度按最小二乘贴合逐点弯曲的原曲线，控制柄连同高度方向一起缩放（两端坡度不变；只缩水平方向时控制柄变短的一头坡度会陡到 20% 以上）。普通路段偏差在厘米级；从主线一直走到被交道路、穿过整个过渡区的长匝道（如菱形 140 米的匝道）与逐点弯曲相差 1 米多——那里的“理想形状”本来就不唯一，弯曲后的坡度、间距另行检查。
- 高度（离地高度 Y）不变。
- 三条臂（Y 型分向，三条臂互不相对、没有主线 / 被交道路之分）：匹配结果给每条臂一条从中心往外的中心线（`TripleLegs` 的 Trace）。点落在相邻两条臂 i、j 之间的扇区里，按这两条臂的斜坐标照上面的公式弯（W_i = A_i(a) + Rot(φ_i(a))·A_j(b)，W_j 对称），混合 t = smoothstep(0.1, 0.9, 0.5 + 0.5·(d_i − d_j) / (d_i + d_j + kSoftness))，中心区两者平均。臂上 W_i、W_j 都等于 A_i(a)，跨过臂进入另一个扇区时连续。斜坐标的横向分量沿相邻那条臂取，它也弯时臂的走廊里横距差几十厘米，所以离中心 120–200 米起走廊里逐渐改按这条臂自己的正交坐标弯（臂上两者相同，仍连续），臂端、分岔处的各幅和匝道精确平行。两条臂都朝同一个扇区弯时那个扇区确实被挤窄（R 500 / 700 时离中心 350 米处夹角从 110° 缩到约 40°），里面的右转匝道跟着变形，弯曲后照样检查坡度、重叠。

## 3. 弯曲后的检查与重算（会更慢的原因）

- 弯道内侧的匝道被压短，坡度变陡（压缩比约 (R − 横距) / R）；外侧被拉长。
- 弯曲后逐段检查坡度；超过上限时把求解用的最大坡度按超出比例收紧（再留 3%），重新配匝道长度、生成、弯曲，最多 3 次（`InterchangeLayout.Bend`）；仍超限时报错，请玩家先把立交范围内的道路调整得平直一些，或加大最大坡度、换一种立交类型。
- 游戏对弯道上的预览报重叠、形状无效时，面板同样提示先把道路调整平直或换类型。

## 4. 工具和面板

- 立交范围（拆除原有道路的凸包）、臂端接回都用弯曲后的路段，臂端落在原有道路上。
- 面板：对准弯道时显示主线 / 被交道路两侧的最小半径，并提示“弯道上的立交按直线算好后整体顺着弯道弯曲：求解较慢，弯道内侧坡度变陡时会自动收紧坡度重算，两条路都弯时匝道会被拉伸或压缩。放置前请仔细检查预览”；收紧了坡度时显示实际用的坡度。
- 两步放置（已做）：左键只固定预览，面板确认才放置——弯道求解慢时不会因为鼠标一动就重算。
