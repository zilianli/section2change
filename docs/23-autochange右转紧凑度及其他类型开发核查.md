# 右转紧凑度与其他立交类型开发核查

## 右转匝道

坡度是最大允许值，不是要求实际坡度。提高上限扩大可行方案集合，但现有搜索按退接距离、环道半径和直连参数的顺序返回第一个通过方案，不对占地或右转长度求全局最小值；因此不能保证每次提高坡度时右转也缩小。

以 2026-10-30 的同高弯路日志端点、合成直线续接、相同车道与桥墩参数为例，现有搜索在 16% 与 27% 下生成的四条右转曲线长度总和约为 2055 米和 1598 米。此例可缩小，但不代表实际原路或所有场景都有同样结果。新增 `GradeCompactnessTests` 固定该对照。

尝试把候选中段由60米改成30米步进，并比较同一退接距离内全部通过候选；该样例结果不变且运行更慢，因此未保留此试验。后续应在真实可追踪道路范围中，对独立环道和右转参数共同求解，明确按四象限占地、右转长度和原路改造距离排序；要说明有界搜索和预算耗尽，不能为了缩小关闭坡度、连续路面净空或桥墩检查。已有自动退接是所有臂统一步进再各自截断，并非完整的非对称退接组合搜索。

## 其他类型当前范围

节点模式在 `InterchangeToolSystem.Nodes.cs` 目前只接入苜蓿叶；其他 12 种仅有端点输入及必要流向合同，不具备节点几何预览。旧 section2change 自动/手动模板与新端点功能的能力分别计算，不能通过解除类型限制或整体平移缩放模板来宣称支持真实端点。

| 类型 | 独立求解的主要要求 |
|---|---|
| 定向 Stack | 四条贯通线及八条定向匝道；区分左右进出和车道平衡，按四层实际交叉求解净空。旧模板仅右侧通行。 |
| 涡轮 Turbine | 四条贯通线、四条半圆左转及四条外围右转；处理真实交叉次序、纵断面、桥墩和车道变化。 |
| 喇叭 | 主线贯通、支路与两条直连、环道和半定向匝道；出口/入口镜像及高差需独立求解。 |
| 定向/半定向 T | 主线贯通加四匝道；远侧左进左出与右进右出有不同交叉及断面。 |
| Y 型 | 三臂、六条有向匝道及三个跨越区，没有贯通主线。 |
| 菱形、单点、部分苜蓿叶、环岛、中式快速路、快速路 T | 各自处理平交、环岛、辅路或转换道路，不沿用苜蓿叶拓扑。 |

建议先提取类型无关的曲线段、路径 ID、精确逻辑节点、非相邻路径净空、退接与支柱约束；现有 `CloverleafRoadClearance` 假设不同匝道在平面分离，不适用于定向多层交叉。保留单独交通侧、宽度与车道变化、每个动作的有向连通和真实曲线高度；未通过的道路形式或约束应明确提示。之后依次实现定向、涡轮，再实现三向及平交类，分别进行生成层与游戏验证。

本次没有开放其他类型预览或正式放置，也没有部署功能改动。此核查不是实现完成的证明。
