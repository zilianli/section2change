# 贴环道高坡度短段与纵坡衔接修复

日期：2026-10-30。autochange / 0.0.1-beta，节点模式临时预览；正式放置仍锁定，没有提交或发布。

## 复现与证据

用户反馈18%附近及以上出现叠放/形状错误，并且匝道纵坡变化不平顺。界面单位为坡度百分比，不是角度。

游戏日志已保存至 `.artifacts/autochange/game-hug-grade-repro.log`。同一组选点中，16%与17%的固定预览未记录游戏错误，18%/20%/25%记录单车道匝道 InvalidShape，30%同时记录单车道匝道、Horizontal Pillar 8 重叠与 InvalidShape。

对 InvalidShape 的 worldCurve 积分：30%时直连终端约10.095m、环道终端约11.473m；18%/20%/25%时约11.804m及14.624m，且报错段两端高度相同。这说明报警与高坡度允许选用的短节点几何相关，不能直接归因于这些段超过道路坡度上限。

原来 SplitFlat 被夹到 `(路径长度-主路保护长度-10)/2`，会把共享分支末段压到10～15m。同时，所有物理路径都用 ApplyWithFlatEnds，使环道前段、共享弧、环道后段以及右转连接弯在每个内部接点附近分别形成平台，升降集中到各自中段。

## 修改

- 共享节点保护长度不再为塞入候选而缩短，使用 `max(20m,2×共享道路宽度)`；当前12m共享道路即24m，放不下就拒绝该候选并继续搜索。该长度是基于本次失败几何采用的保守设计约束，不是已经证明的通用游戏安全阈值。
- 把“允许接点附近重叠的保护段”和“需要水平的主路衔接段”分开。主路分流/汇入保持水平，内部共享接点允许携带连续纵坡。
- 从完整原环道的平滑纵断面计算两个共享接点的高度和坡度。LoopIn/LoopOut沿环道方向，Shared反向坡度取反，右转连接弯按Shared方向接续。各路径端高、切线及有符号纵坡衔接一致；不再在每个共享接点插入有限长度平台。
- VerticalProfile增加 ApplyWithBoundaryGrades，支持水平区间外的指定端坡；旧接口以零端坡委托，普通苜蓿叶和其他使用方行为保持。每段仍做最大坡度认证；没有提高30%上限或屏蔽游戏报错。
- 保护段仍按原有首末曲线界定；碰撞豁免只限共用精确3D逻辑节点的终端曲线，其他路面和桥墩检查保留。

## 验证

- 修复前新增7项回归全部失败，明确抓到短终端段及内部接点平台。
- 修复后80项针对性测试通过，包括16%、17%、18%、20%、25%、30%日志端点复现，至少24m的终端保护长度，接点正反向坡度连续、非零端坡及高度不反向起伏。
- 生成层全量1398/1398通过，0失败、0跳过；Release Mod构建成功。保留既有StackTemplate可空性和xUnit断言风格警告。本轮没有修改UI。
- 原R60/连接半径80m/共享宽16m/高差10m案例，之前因为多处平台导致GradeExceeded；连续端坡方案现在通过最大坡度和8.5m净空检查，两种行车方向均通过。前一轮报告中的拒绝结果已被本轮方案改善。
- 复现端点来自真实日志；端点外续路为合成600m路径，不是原存档道路曲线完整捕获。
- 独立静态复核未发现阻断问题；这些是代码与生成层测试结论，原场景游戏报警是否消失及实际外观仍需复测。

证据：`test-results/hug-grade-red.trx`、`hug-grade-targeted.trx`、`hug-grade-final.trx`、`build-hug-grade-final.log`，均位于 `.artifacts/autochange`。

用户正常退出游戏后已部署；26/26安装文件SHA256与暂存包一致，安装版本0.0.1-beta。原包备份：`.artifacts/autochange/installed-before-hug-grade-20261030-223820`；核验清单：`.artifacts/autochange/deployment-hug-grade-manifest.json`。

## 游戏回测

在原组选点保持贴环道、层高和退接上限不变，依次生成16%（对照）、18%、20%、25%、30%预览。每次停留5秒检查面板和游戏图标；重点看共享分支短段、单车道匝道与横向桥墩是否仍报警，以及环道和右转是否连续升降、没有明显台阶或多次平台。若失败保留固定预览并记录坡度，日志可直接对应本轮实体位置。
