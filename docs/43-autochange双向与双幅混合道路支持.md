# autochange 双向与双幅混合道路支持

版本：`0.0.1-beta`；分支：`autochange`；本轮日期：2026-11-02。

## 范围与输入

玩家已反馈上一轮环岛及节点确认放置测试“通过”，本轮按玩家选择优先扩展现有类型的道路适配。该反馈不代表九种类型、所有车道组合和左右行极值均完成实机验收。

每个方向可选择一个对称双向道路开放端点，或一进一出的两个单向道路开放端点。不同方向可以混用。四向立交共有4～8个实际端点，三向立交共有3～6个。相对贯通道路仍须符合既有车道和断面约束；不是任意道路都可相互连接。

| 现有类型 | 新增输入路径 | 保留的要求或选项 |
| --- | --- | --- |
| 苜蓿叶 | 双向、双幅与混合 | 普通外侧右转、贴环道；贴环须有准确对应的双向共享匝道预制体 |
| 定向 | 双向、双幅与混合 | 右出右进、左出左进，沿用核心车道平衡 |
| 涡轮 | 双向、双幅与混合 | 沿用既有三层核心与分合流 |
| 喇叭 | 双向、双幅与混合 | 三向输入；环道用于驶出或驶入主线 |
| 定向T | 双向、双幅与混合 | 三向输入；既有两层／三层和层高限制 |
| 半定向T | 双向、双幅与混合 | 三向输入；既有两层／三层和层高限制 |
| Y型 | 双向、双幅与混合 | 每方向车道数为偶数，以准确分配两条分支 |
| 井字 | 双向、双幅与混合 | 每方向至少三车道，准确分配直行与集散 |
| 环岛 | 双向、双幅与混合 | 圆形、跑道形，沿用既有环道道路选择 |

以上是新增代码路径与数学验证范围，实际原生网格、车道连接和车辆通行仍待本轮游戏测试。

部分苜蓿叶按玩家要求跳过。梅花不恢复；菱形、单点和中式快速路不加入新节点类型。

## 实现

- 按原双向路每方向真实车道数，寻找同类且准确匹配的真实单向道路。找不到对应道路、车道不对称、含专用公交车道或原核心不支持的组合会明确失败，不静默减少车道。
- 内部复用已经存在的双幅立交核心。双向道路外侧增加保留原预制体的双向干线，再通过两条单向转换曲线接入核心。转换按左右行布置，保持真实切点的三维位置、切向和每方向车道数。
- 数学代理端点仅用于求解。最终删除范围、接回节点和保留尾段从原始真实道路重新切分；发射临时定义前，再以完整重新切分快照核对实际来源。代理实体身份不进入原生改造命令。
- 转换空间计入各臂可见退接范围，最大仍为每臂1000米、坡度30%。弯路实际改造曲线使用保守弧长上界复核距离；内部核心、转换曲线及各跨长分配尝试共享最多128个候选预算。
- 全网络使用实际预制体宽度、层高包络、跨度和桥墩数据复核。转换道路使用独立路径标识，不能以共享标识跳过彼此碰撞。同一精确三维逻辑节点的相接首末段，端点支撑解析包络交给原生临时道路检查；中部支撑和无关道路不豁免。此处不推定不同道路预制体一定合并成一个真实桥墩。
- 新路径复用既有确认流程：实际来源快照、界面显示修订号、同一原生临时批次稳定检查、只读重验后提交一次。全双幅原有求解路径保持。没有自动开启无碰撞或屏蔽游戏阻止错误。

## 建议的游戏测试顺序

1. 先用测试存档做环岛：四个方向各选一个双向道路端点。生成预览，核对两股车流转换侧向、白点接回位置及虚线改造范围；待原生检查通过后确认放置。
2. 再做混合环岛：主线两端用双幅道路，被交两端用每方向车道数相符的双向道路。检查真实原路接回、保留尾段、范围外道路及双向转换处车道连接。
3. 按苜蓿叶、定向、涡轮、三向类型、Y型、井字逐类复测。苜蓿叶分别测普通和贴环；定向分别测两种出入口。Y型用每方向偶数车道，井字用每方向至少三车道。
4. 基础放置通过后再测弯路、混合高度和左右行。每次放置后让车辆通行，再保存重载复查；另测取消和参数变化后旧确认失效。

转换段需要额外空间，可能增加退接距离。在目录或几何约束不能满足时，保留失败提示与原路，不能保证所有短距离输入都生成。
