# autochange 井字方位归组修复

2026-11-01，autochange，0.0.1-beta。处理用户首次井字测试“预览失败”，正式放置锁定，不提交或发布。

## 原因与证据

01:57的日志显示8个合法开放端点，均为每幅4车道、20米宽的Highway Oneway道路。实际道路相邻接近90°，端部高程约488.632米与500.42～500.67米，参考地形约478.632米。原输入分组为南/西/东/北，程序却直接将方向1/3、2/4视为相对臂，错误地把南/东和西/北当成两条贯通道路。

核心因此0次接路尝试就返回“需要80～100°相对道路家族”。该问题发生在输入解释阶段，增加退接上限、坡度或层差无法纠正。安装包27个文件全部与上一部署清单匹配，排除了旧DLL或UI文件未更新。

冻结日志：`.artifacts/autochange/game-grid-order-failure.log`。测试资源 `grid-order-failure-20261101.json` 保存8条真实原路及106段曲线，包含节点索引/版本、Prefab、宽度、车道、行驶方向、三维位置、切线和原路片段。

## 修复行为

- 仅井字输入按四组端点真实方位整理为顺时针编号，原方向1作为起点，真实相对道路成为新方向1/3和2/4。
- 每组仍由玩家选择一进一出的同侧双幅端点；四组可按任意顺序选。选齐后自动识别，颜色编号和活动分组同步调整，不丢点或改写节点身份。
- 原端点对象、世界坐标、高程、切线和每臂退接上限一同保留或对应重排；原输入数组不变。
- 共用运行时选择重建由固定三臂改成实际臂数，避免四臂排序后继承T型逻辑而越界。
- 仅在四组方位明确且符合井字交角范围时整理，之后重新完整校验；重复端点、无效方向和不一致断面仍拒绝。未扩大交角、坡度、净空或桥墩限制。
- 已验证的T、Y及其他四向类型保留原处理路径。UI说明更新为井字自由分组后自动整理。

## 验证

修复前54项测试中42失败、12通过，包含真实场景无法生成的同一错误。修复后54项全部通过：24种分组排列乘以左右侧通行、不同道路家族的正确相对匹配、独立退接上限映射、快照保持、重复输入拒绝与旧四向约定保护。

真实场景以原参数16%最大坡度、1000米每臂上限、基层偏移0、自动层差回放成功：四方向退接275/275/275/250米，1次完整接路尝试，130段临时道路；严格坡度、实际道路包络净空和桥墩认证通过。道路支撑规则依据目录日志，未单独记录的桥墩包络采用既有保守假设，因此不替代游戏原生检查。

260项针对性回归、UI类型检查/webpack、Release构建通过；独立只读复核未发现阻断项。完整回归1934项全部通过，失败0、跳过0，持续6分24秒，结果见 `.artifacts/autochange/test-results/grid-order-full.trx`。
