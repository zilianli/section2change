# autochange 苜蓿叶贴环道及紧凑化测试包

日期：2026-10-30。分支 autochange，版本 0.0.1-beta。节点模式仍是临时预览，正式放置锁定。没有提交、推送或发布。

## 本轮实现

- 节点菜单增加现有“外侧大弧线 / 贴环道”选择，沿用 CloverleafHugLoop 设置。选项变化使旧预览失效，点击“生成预览”重新求解。
- 贴环道使用每象限一段真实双向共享弧线：外侧右转正向通行，内侧环道反向通行。两端分别生成连接弯和环道分支，逻辑节点精确共用，道路仅生成一次。环道中心半径 R，共享道路中心半径 R+W/4，右转车道中心半径 R+W/2；参考旧 section2change 的 TryHug 几何。
- 自动选择双向道路要求正反两个方向分别等于匝道车道数，排除含公交专用道、非有限宽度和过窄道路；优先同道路规则。缺失匹配明确报错，不回退成普通版。
- 对共享弧及四类连接路径分配独立 PathId、高度因子、宽度和预制体。共享节点附近只有规定首末保护段可重叠，其他部分继续做真实宽度和 8.5m 竖向净空检查。相关反例会拒绝同 SourceArm/Kind、不同 PathId 的交叉。
- 共享高度由原环道平滑高度比例分配，所有分支再分别检查平段和最大坡度；不满足时拒绝并尝试更大的几何组合。连接较短时不能假定双向共享段必然能解决高差。
- 贴环道使用独立半径网格，不重复普通版无效的中段长度候选。保留原道路真实退接、20°端部适配、精确接点、高差适配、主路减车道/中央交织全宽和中央桥墩规划。
- 普通版首个完整通过方案之后增加至多24次局部搜索，固定真实截点及环道，缩短右转参数；每次重做坡度、路面和桥墩检查。失败保留原通过方案，计入总候选预算。是有界局部改善，不保证全局最小体积。

## 游戏测试顺序

1. 复制存档中暂停游戏，四方向各选择一进一出的双幅道路。当前不支持双向单幅/双幅混合转换，也不支持贯通两端不同路型。
2. 同一组选点测试“外侧大弧线”：16%与27%比较整体占地、右转转弯是否平滑、主路缩道是否合理，不要求每个场景都随坡度单调变小。
3. 切换“贴环道”并重新生成：确认四象限都出现双向共享弧、两处分支平滑、不出现重复路面/叠放/坡度/形状错误；记录面板所选共享道路名称。
4. 在已有混合高度及弯曲原路场景重复两种样式，检查白色新接点、退接虚线范围、外部道路高度和切线、中央跨线净空、实际桥墩是否压路。
5. 缩小退接上限或改变层高，失败时应明确提示且清除旧预览；切换普通/贴环道及退出工具后不应残留临时道路。

正式放置、存档加载后连接、实际车道走向/交通仿真和所有游戏桥墩形态仍未验证。暂不强制开启无碰撞辅助，不屏蔽游戏报错。苜蓿叶两种样式完成这轮测试后，继续定向与涡轮，再推进三向和其他类型；当前其他类型仍只有输入契约，未宣称已实现。
