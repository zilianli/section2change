# 井字分合流边缘对齐修复

2026-11-01，autochange，0.0.1-beta。处理玩家两组预览中汇入区域“无效形状”与接入曲率反馈，正式放置继续锁定，不提交或发布。

## 原生反馈与定位

本轮日志冻结为 `.artifacts/autochange/game-grid-native-shape-failure.log`。03:30为直路/混合高程，03:31为既有真实弯路，均在生成候选成功之后报告双车道道路InvalidShape。日志中对应报错的target为none，未记录这两组的OverlapExisting；因此不能将截图中的接入问题直接等同于桥墩或旧路叠放。

报错集中在全宽道路分成直行与集散道、以及两者重新合入全宽道路的首/末段。此前两条减道曲线均从同一个中心线位置、同向相切出发。平面曲率缓和、分隔带余量、坡度和数学净空均通过，仍不能证明原生节点形状有效。

现有section2change的StackTemplate车道平衡，采用曲线端点偏移而逻辑节点不动；NodePreviewPlacer和NetCourseBuilder也分别传递WorldCurve与StartNode/EndNode，已经支持这一契约。本轮沿用此方法，修正井字分合流的断面衔接。

## 修复

- 直行减道曲面的外侧边缘对齐全宽道路外缘，集散道曲面的内侧边缘对齐另一侧边缘。偏移各为 `(全宽道路宽度-对应减道宽度)/2`，按照真实道路元数据计算。
- 20米全宽道路分成两条12米道路时，曲线端点分别向两侧偏移4米，不再重合在一条中心线上。左右通行、入/出两侧分别映射，两个曲面仍连接同一个原逻辑节点。
- 跨距细分只在整链最外端保留原分合流逻辑节点，新增内部节点仍使用自身真实曲线端点，不把中间桥墩节点误合并回汇入点。
- 横移长度按边缘对齐后的真实剩余位移重算。既有端部零曲率缓和、横移与爬坡合并、严格坡度、完整网络净空、原分隔带缓冲及真实桥墩检查继续执行。
- 外部八个真实道路端点及其切向不变，20条逻辑道路链和12个方向动作继续验证。原生发射接口无需修改。

## 证据与验证

原核心回归从“所有曲线端点必须等于逻辑节点”的旧断言改为明确检查：若二者不同，该逻辑节点必须恰有3条相接道路，包含唯一最宽全幅道路；偏移必须垂直于全幅切向、与宽度差完全对应且高程相同。内部普通节点及外部端口仍保持原契约，不取消连通性认证。
